# خطة تنفيذ تحديث تطبيق سوق المناسبات

> **لـHermes:** تُنفّذ الخطة مرحلةً مرحلة، مع اختبار كل مرحلة قبل الانتقال إلى التالية.

**التاريخ:** 2026-09-03  
**المشروع:** `/opt/shihab-marketplace`  
**النطاق:** تطبيق Flutter للمستخدم + سلوك GPS + تصميم الصفحة الرئيسية والشريط السفلي

## الهدف

تنفيذ أربعة تحديثات مترابطة في تطبيق سوق المناسبات:

1. تحويل التصنيفات الكبيرة إلى شريط تصنيفات مختصر ومتناسق.
2. إصلاح GPS كلياً مع تمييز مصدر الموقع ومعالجة الصلاحيات وإعدادات النظام.
3. تثبيت البحث وشرائح «مفتوح الآن / الأقرب إليك / الأقل سعراً» أثناء السكرول، مع تلاشي الهيدر العلوي فقط.
4. تحديث الشريط السفلي إلى تصميم Floating Dock هادئ يحافظ على التبويبات الخمسة.

## الحالة الحالية المؤكدة

- التصنيفات في `frontend/lib/features/shell/root_scaffold.dart` تستخدم كروتاً بعرض 84 وارتفاع حاوية 108، لذلك تبدو كبيرة.
- التحية والموقع والبحث والشرائح كلها داخل `SliverToBoxAdapter` واحد، لذلك تختفي معاً عند السكرول.
- شريحة «مفتوح الآن» تمرر `openNow: true`، بينما شريحتي «الأقرب إليك» و«الأقل سعراً» لا تمرران حالياً `nearby` و`lowestPrice` رغم وجود دعم لهما داخل `ExploreScreen`.
- ارتفاع الشرائح الحالية 34px، وهو أقل من منطقة اللمس المعتمدة 48px.
- `main.dart` يشغّل `_autoLocate` عند الإقلاع قبل تفاعل المستخدم.
- `session_service.dart` يحاول GPS ثم ينتقل تلقائياً إلى `ipapi.co`، ويحفظ الاثنين داخل `sm_lat` و`sm_lng` بدون مصدر أو دقة.
- حالات `deniedForever` وفتح إعدادات التطبيق/الموقع غير معالجة.
- صلاحيات `ACCESS_COARSE_LOCATION` و`ACCESS_FINE_LOCATION` موجودة في `AndroidManifest.xml`؛ لذلك لن نضيف صلاحيات غير لازمة.
- الشريط السفلي الحالي `NavigationBar` قياسي بارتفاع 68px.

## القرار التصميمي

### التصنيفات

شريط أفقي Compact بارتفاع مرئي 78–82px:

- مربع أيقونة 36×36، نصف قطر 10px.
- اسم التصنيف في سطر واحد.
- بلا كروت كبيرة أو دوائر.
- تحديد التصنيف بحد/خلفية Deep Teal.
- منطقة لمس لا تقل عن 48×48.

### الهيدر أثناء السكرول

- الهيدر العلوي: تحية + موقع + إشعارات + الخط الذهبي، ويبقى ضمن جزء قابل للتلاشي.
- شريط البحث والشرائح: `SliverPersistentHeader(pinned: true)`.
- التلاشي فقط خلال مسافة قصيرة، بدون تكبير أو Parallax.
- خلفية ثابتة وحد سفلي محايد حتى لا يتداخل المحتوى أثناء التثبيت.

### الشريط السفلي

Floating Dock هادئ:

- خلفية سطح التطبيق، حد خفيف، ظل محايد.
- حواف مستديرة 16px.
- ارتفاع تقريبي 76–80px مع SafeArea.
- العنصر النشط داخل مربع مستدير 40×40، وليس دائرة.
- إبقاء أسماء التبويبات الخمسة واضحة.

## مراحل التنفيذ

### المرحلة 1: اختبار GPS قبل الإصلاح

**الملفات:**

- إنشاء: `frontend/test/location_service_test.dart`
- تعديل لاحقاً: `frontend/lib/core/session/session_service.dart`

**الاختبارات المطلوبة:**

- حالة صلاحية مرفوضة.
- حالة `deniedForever`.
- خدمة الموقع مغلقة.
- نجاح GPS.
- انتهاء المهلة.
- عدم اعتبار موقع IP موقع GPS.
- حفظ المصدر والدقة والتاريخ بشكل منفصل عن الإحداثيات.

**التحقق:**

```bash
cd /opt/shihab-marketplace/frontend
flutter test test/location_service_test.dart
```

المتوقع قبل الإصلاح: حالات المصدر/الفشل غير ممثلة أو غير قابلة للاختبار. لا نعتبر ذلك فشلاً في التطبيق؛ الهدف إنشاء اختبار كاشف قبل التعديل.

### المرحلة 2: إصلاح GPS ومسار الصلاحيات

**الملفات:**

- تعديل: `frontend/lib/core/session/session_service.dart`
- تعديل: `frontend/lib/main.dart`
- تعديل: `frontend/lib/features/location/location_picker.dart`
- لا تعديل مخطط له: `frontend/android/app/src/main/AndroidManifest.xml` إلا إذا كشف build أو الاختبار نقصاً حقيقياً.

**التغييرات:**

1. إيقاف طلب GPS التلقائي قبل ظهور الواجهة.
2. جعل تحديد الموقع يبدأ من ضغط المستخدم على زر واضح.
3. تمييز النتائج: GPS حقيقي / موقع تقريبي اختياري / فشل.
4. معالجة `deniedForever` مع `Geolocator.openAppSettings()`.
5. معالجة إيقاف الخدمة مع `Geolocator.openLocationSettings()`.
6. عرض رسالة مختلفة لكل سبب بدلاً من `catch (_) {}` الصامت.
7. رفع مهلة GPS إلى قيمة عملية مع استخدام آخر موقع معروف عند توفره.
8. عدم حفظ موقع IP في مفاتيح GPS نفسها.
9. منع محاولة GPS المتأخرة من استبدال مدينة اختارها المستخدم يدوياً.
10. حفظ موقع ناجح مع المصدر والتاريخ، وإعادة استخدامه فقط وفق سياسة واضحة.

**التحقق:**

```bash
cd /opt/shihab-marketplace/frontend
flutter test test/location_service_test.dart
flutter test
```

ثم اختبار Android حقيقي للحالات: السماح، الرفض، الرفض النهائي، GPS مغلق، وداخل مكان مغلق.

### المرحلة 3: تثبيت البحث والشرائح أثناء السكرول

**الملفات:**

- تعديل: `frontend/lib/features/shell/root_scaffold.dart`
- تعديل: `frontend/lib/features/explore/explore_screen.dart` عند الحاجة لاختبار المعاملات.
- اختبار: `frontend/test/widget_test.dart` أو إنشاء اختبار واجهة مخصص تحت `frontend/test/`.

**التغييرات:**

1. تحويل `HomeScreen` إلى stateful consumer مع `ScrollController`.
2. فصل الهيدر العلوي عن منطقة البحث والفلاتر.
3. إضافة `SliverPersistentHeader(pinned: true)` للبحث والشرائح.
4. تطبيق تلاشي تدريجي للهيدر فوق الخط الذهبي فقط.
5. إبقاء البحث والشرائح ثابتة، ثم السماح للتصنيفات والبائعين بالسكرول الطبيعي.
6. رفع منطقة لمس الشرائح إلى 48px مع إبقاء شكلها المرئي compact.
7. ربط الأزرار فعلياً:
   - `ExploreScreen(openNow: true)`.
   - `ExploreScreen(nearby: true)`.
   - `ExploreScreen(lowestPrice: true)`.
8. التحقق من أن اختيار «الأقرب» يرسل lat/lng/radius، وأن «الأقل سعراً» يرسل sort=price.

**التحقق:**

- اختبار أن الهيدر العلوي يختفي تدريجياً.
- اختبار أن البحث والشرائح يبقيان ظاهرين بعد السكرول.
- اختبار أن التصنيفات والبائعين يمران خلف منطقة التثبيت بشكل صحيح.
- اختبار ضغط الشرائح والتحقق من المعاملات المرسلة إلى API.
- التأكد من عدم وجود overflow على عرض 320 و360 و412px.

### المرحلة 4: تصغير التصنيفات

## ملفات وقواعد ممنوع لمسها

- لا تغيير كلمات المرور أو الحسابات الموجودة.
- لا حذف أو تفريغ قاعدة البيانات.
- لا تعديل إعدادات Hermes أو ملفات `~/.hermes`.
- لا تعديل خدمات أو شاشات خارج نطاق GPS والصفحة الرئيسية والشريط السفلي.
- لا استخدام fallback صامت يجعل المستخدم يظن أن موقع IP هو GPS.

## معيار القبول النهائي

- GPS يعطي حالة واضحة ويعيد المحاولة بطريقة صحيحة بعد معالجة الصلاحية.
- لا يتم استبدال اختيار المدينة يدوياً بطلب GPS قديم.
- البحث والشرائح تبقى مثبتة بعد السكرول، وما فوق الخط الذهبي يتلاشى فقط.
- التصنيفات compact ولا تسبب ازدحاماً أو أهداف لمس صغيرة.
- الشريط السفلي محدث بصرياً ويحافظ على التنقل والتسميات.
- `flutter test` يمر.
- APK release مبني ومطابق للرابط العام.
- كل نتيجة غير قابلة للتحقق على جهاز حقيقي توسم بوضوح كاختبار مطلوب من المستخدم.
