# USER FLOWS — تدفقات المستخدم المفصلة

قراءة المخططات: ← مسار رئيسي، ←(بديل) فروع، ◇ قرارات. كل Flow يختم بحالة نهائية واضحة.

## F1 — حجز خدمة (Customer Booking) — الأهم

```
Vendor/Service Details
   │
   ├─[اختر Book Now]
   ▼
الخطوة 1: التاريخ ◇ — Calendar يظهر التوفر مسبقاً (متاح/مزدحم/مغلق)
   │                (يوم غير متاح = معطّل + سبب مختصر عند اللمس)
   ▼
الخطوة 2: الوقت — TimeSlots (متاح/محجوز/فترة قريبة)
   │    ←(لا فترات؟) → اقترح أقرب تاريخ متاح بدل طريق مسدود
   ▼
الخطوة 3: المورد/الإضافات — قاعة معينة، موظف معين، Add-ons (تصوير/ديكور)
   ▼
الخطوة 4: بيانات العميل — معبأة مسبقاً من البروفايل (لا إعادة إدخال)
   ▼
الخطوة 5: الملخص — سعر نهائي مجمد 15 دقيقة + كود خصم
   ▼
الدفع — طريقة محفوظة/جديدة
   │    ◇ نجاح؟
   │    ├─ نعم → شاشة تأكيد (رقم حجز + إضافة للتقويم + تتبع)
   │    └─ لا → رسالة مفهومة + إعادة المحاولة/طريقة بديلة (الحجز محفوظ PENDING)
   ▼
Booking Tracking (قادم، مع أزرار: تواصل/إلغاء حسب السياسة)
   ▼
بعد انتهاء الخدمة → طلب التقييم (يقيّم المشتري فقط)
```

**قواعد ملزمة:** التقدم يحفظ كل خطوة (رجوع = لا فقدان بيانات)؛ التوفر يظهر قبل أي طلب دفع؛ CTA رئيسي واحد بكل شاشة.

## F2 — طلب مطعم/هدايا (Orders)

```
Vendor (مطعم/هدية) → أضف للسلة → السلة (تعديل كمية/ملاحظات)
→ العنوان (محفوظ/جديد) → موعد التسليم (فوري/مجدول)
→ الدفع → تتبع بـ Timeline:
[مؤكد] → [قيد التحضير] → [جاهز] → [في الطريق] → [تم التسليم]
                              ←(إلغاء حتى قبل التحضير)→ CANCELLED
```

## F3 — Plan My Event

```
بانر «خطط مناسبتك»
→ الخطوة 1: نوع المناسبة (عرس/خطوبة/ميلاد/تخرج/شركات/أخرى)
→ الخطوة 2: ضيوف + تاريخ + مدينة + ميزانية (Slider بفئات)
→ الخطوة 3 (اختياري): تفضيلات (فنژون/داخلي، كشر، موسيقى...)
→ توليد: بطاقات بنود (قاعة/ضيافة/تصوير/ديكور/كيك/تجميل/هدايا)
   كل بند: 3 بدائل (اقتصادي/مميز/VIP) + إجمالي تقديري حي
→ تعديل البنود (استبدال بدل حذف)
→ [حوّل الخطة لحجوزات] → ينشئ Bookings مسودة لكل بند مقبول → F1 لكل بند
```
AI غير مرئي كـ«روبوت» — الواجهة «خطة» بصيغة بشرية مع سبب كل اقتراح بسطر واحد.

## F4 — رحلة البائع (Vendor Onboarding → أول حجز)

```
تسجيل بائع (خطوتان فقط) → حالة: قيد التحقق (شاشة صافية تشرح المتبقي)
→ (Admin يوافق) → إعداد النشاط (Wizard 4 خطوات، حفظ تلقائي):
   [1] معلومات + صور  [2] موارد (قاعة1/حلاق1...)  [3] خدمات وأسعار  [4] توفر أسبوعي
→ نشر (ممكن بخدمة واحدة فقط)
→ Dashboard: «لا حجوزات بعد» + نصيحة إكمال البروفايل
→ أول طلب حجز → [مراجعة الطلبات] → قبول/رفض بضغطة (+ سبب الرفض الموحد)
→ يوم الخدمة → إنهاء → يظهر في الأرباح (إجمالي/عمولة/صافي)
```

## F5 — Admin: verification queue

```
Dashboard → تنبيه «3 بائعون بانتظار التحقق»
→ قائمة جدولية (اسم/تاريخ/نوع/أولوية) → تفاصيل Drawer
→ [اعتماد] / [رفض + سبب من قائمة] / [طلب مستندات]
→ تسجيل تلقائي في Audit Log + إشعار للبائع
```

## F6 — حالات الفشل المشتركة (لكل Flow)
| الحدث | الاستجابة |
|---|---|
| انقطاع شبكة أثناء دفع | الحجز يبقى PENDING، بانر «سنحاول تأكيد الدفع تلقائياً» + زر إعادة |
| الصالة حجزت اللحظة نفسها (نادر) | 409 → «آسفون، الفترة حُجزت للتو» + 3 بدائل فورية قريبة |
| خطأ خادم | «حدث خطأ... أعد المحاولة» + معرّف تقرير، بلا مصطلحات تقنية |
| جلسة منتهية | صمت ثم refresh توكن؛ إن فشل → شاشة دخول مع الحفاظ على المسار المقصود |
