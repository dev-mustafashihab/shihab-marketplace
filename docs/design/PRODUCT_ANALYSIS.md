# PRODUCT ANALYSIS — التحليل والشخصيات والرحلات

## 1) تحليل المنتج

**المنتج:** Marketplace عربي-first لحجوزات المناسبات والخدمات المحلية + طلبات (مطاعم/هدايا).
**الوعد الأساسي للمستخدم:** «جد الخدمة المناسبة، تأكد أنها متاحة، احجز وادفع بدقائق — بدون مكالمات».
**ركائز التجربة:** الثقة (توثيق + تقييمات) → السرعة (حجز ≤ 90 ثانية) → الوضوح (السعر النهائي والتوفر قبل الدفع).

**نموذج الاستخدام الغالب:** موبايل أولاً، شبكات ضعيفة أحياناً، مستخدم عربي يفضّل الوضوح على الزخرفة.

## 2) الشخصيات (Personas)

### P1 — أحمد، عميل (28 سنة، دمشق)
- يجهز عرس أخته؛ يبحث عن صالة + تصوير + ديكور بميزانية محددة.
- **احتياجه:** مقارنة سريعة بالسعر/السعة/التقييم، تأكيد التوفر فوراً، أرشيف حجوزاته.
- **خوفه:** يدفع ثم يُقال له «التاريخ محجوز».
- **جهازه:** أندرويد متوسط، يكره الشاشات المزدحمة والفورمات الطويلة.

### P2 — أم سارة، عميلة (35 سنة)
- تحجز صالون + طلبات هدايا أسبوعياً؛ تكرر الطلب من نفس الأماكن.
- **احتياجها:** إعادة الحجز بضغطة، المفضلة، إشعارات العروض، حالة الطلب لحظياً.

### P3 — أبو خالد، صاحب صالة (بائع)
- يعمل على هاتف في الصباح وحاسوب ليلاً.
- **احتياجه:** رؤية حجوزات اليوم في 3 ثوانٍ، قبول/رفض بضغطة، معرفة أرباحه وعمولة المنصة بوضوح.
- **خوفه:** تعقيد الإعداد الأولي (موارد + توفر) فيثبطه قبل الإكمال.

### P4 — مدير المنصة (Admin)
- Desktop-first؛ يتحقق من البائعين، يعدل العمولة، يتابع النزاعات.
- **احتياجه:** جداول + فلاتر + إجراءات جماعية + Audit — لا Cards بلا معلومات.

## 3) الرحلات (Journeys) — ملخص تنفيذي

### عميل — حجز كامل
```
فتح التطبيق ← تحديد الموقع ← الرئيسية ← تصنيف ← بحث/فلاتر ← صفحة البائع
← الخدمة ← التوفر (Calendar) ← الحجز (Multi-step) ← الملخص ← الدفع ← التأكيد
← تتبع الحجز ← التقييم
```
نقاط الانسحاب الحرجة (نعالجها بالتصميم): اختيار التاريخ (نعرض التوفر مبكراً)، الدفع (سعر نهائي ثابت + Idempotency)، ما بعد الدفع (شاشة نجاح واضحة + مسار تتبع).

### بائع — من التسجيل للإيراد
```
تسجيل ← تحقق ← إعداد النشاط ← إضافة الموارد ← الخدمات/الأسعار ← التوفر
← استلام طلب حجز ← قبول/رفض ← تنفيذ الخدمة ← الأرباح/السحب
```
Onboarding البائع مقسم خطوات قصيرة مع حفظ تلقائي — يمكنه النشر بخدمة واحدة ثم الإكمال لاحقاً.

### Plan My Event (مميّز تنافسي)
```
ما المناسبة؟ ← عدد الضيوف/التاريخ/المدينة/الميزانية ← تفضيلات
← خطة مقترحة (قاعة/ضيافة/تصوير/ديكور/كيك/تجميل/هدايا) بإجمالي تقديري
← تعديل البنود ← تحويل البنود إلى حجز فعلي
```
AI خلف الكواليس، لا يظهر كـ«شات بوت» في الواجهة — يظهر كـ«خطة جاهزة قابلة للتعديل».

## 4) مؤشرات نجاح UX
- زمن حجز كامل (من الرئيسية للتأكيد) ≤ 90 ثانية لمستخدم متكرر.
- نسبة إكمال Checkout ≥ 85%.
- صفر شاشات «No Data» المجردة؛ كل فراغ فيه فعل تالٍ مقترح.
