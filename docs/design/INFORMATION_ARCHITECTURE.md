# INFORMATION ARCHITECTURE — معمارية المعلومات

## 1) مبدأ التنظيم
شجرتان منفصلتان بالكامل (Customer / Vendor) مع لوح Admin ثالث Web Desktop-first. لا تختلط مسارات البائع بمسارات العميل إطلاقاً — دخول البائع بعدلة تسجيل مختلفة وواجهة مختلفة الهوية.

## 2) Bottom Navigation — عميل (5 تبويبات، كل عنصر مبرر)

| التبويب | لماذا يستحق مكاناً؟ | المحتوى |
|---|---|---|
| الرئيسية | نقطة البدء: موقع + بحث + اقتراحات ذكية | بحث، تصنيفات، عروض، قريب منك، باقات، recently viewed |
| استكشف | استهداف واعٍ (أعرف ما أريد تقريباً): بحث + خريطة + فلاتر | نتائج، فلاتر محفوظة، خريطة/قائمة |
| حجوزاتي | القيمة الأساسية بعد الدفع — فحص متكرر | حجوزات قادمة/سابقة، حالة كل حجز، إعادة حجز |
| طلباتي | تتبع المطعم/الهدايا Timeline لحظي | طلبات نشطة/سابقة، إعادة طلب |
| حسابي | هوية، عناوين، إعدادات، محفظة، دعم | بروفايل، عناوين، مفضلة (دخول ثانوي)، إشعارات، لغة، دعم |

**مستبعد من الشريط عمداً:** المفضلة (كثافة استخدام أقل — تُفتح من الرئيسية والحساب)، Plan My Event (CTA بارز داخل الرئيسية + استكشف، لا يستحق tab دائم). كل عنصر بالشريط يجب أن يُفتح يومياً بواقعية.

## 3) خرائط المحتوى

### عميل
```
BottomNav
├─ الرئيسية
│  ├─ Location bar ← تغيير المدينة/الموقع
│  ├─ Search bar ← Search
│  ├─ Categories (أفقية) ← Category
│  ├─ Plan My Event (بانر CTA) ← Event Planner
│  ├─ Special Offers (أفقية) ← Offer/Vendor
│  ├─ Near You (Vendor cards) ← Vendor Details
│  ├─ Popular Services ← Service Details
│  ├─ Event Packages ← Package Details
│  └─ Recently Viewed
├─ استكشف (Search / Results)
│  ├─ بحث نصي + اقتراحات
│  ├─ فلاتر: تصنيف، سعر، تقييم، مسافة، سعة، متاح الآن
│  └─ تبديل قائمة/خريطة
├─ حجوزاتي (قادمة/سابقة) ← تفاصيل حجز ← تقييم / إعادة حجز / دعم
├─ طلباتي ← تفاصيل طلب (Timeline) ← إعادة طلب
└─ حسابي
   ├─ الملف الشخصي / العناوين
   ├─ المفضلة
   ├─ الإشعارات
   ├─ المحفظة (لاحقاً)
   ├─ اللغة (عربي/English)
   └─ الدعم (شات)
```

### بائع (تطبيق/ويب موبايل — Drawer + شاشة رئيسية Task-first)
```
Vendor Home (لوحة اليوم)
├─ حجوزات اليوم / قائمة الانتظار (Pending) ← Review Requests
├─ التقويم ← مورد/يوم
├─ الموارد والخدمات (CRUD)
├─ التوفر (قواعد أسبوعية + إغلاقات)
├─ الطلبات (مطعم/منتجات إن وجدت)
├─ الأرباح (إجمالي/عمولة/صافي/سحوبات)
├─ التقييمات
└─ الإعدادات (فريق العمل، سياسات الإلغاء)
```

### Admin (ويب Desktop-first)
```
Admin Shell (Sidebar)
├─ Dashboard (KPIs)
├─ Users / Vendors / Verification queue
├─ Categories / Services / Products
├─ Bookings / Orders / Refunds
├─ Commissions / Payouts
├─ Reviews / Complaints
├─ Coupons / Promotions
├─ Notifications (broadcast)
├─ Settings (عمولة، رسوم، ضرائب)
└─ Audit Logs
```

## 4) قواعد تنقل
- عمق أقصى 3 مستويات؛ أي مسار أعمق يتحول لخطوات (Stepper) أو BottomSheet.
- الحجز والـ Checkout: خط أمامي (لا Tabs جانبية) مع حفظ حالة بين الخطوات.
- «رجوع» لا يفقد المدخلات أبداً (حالة الحجز تبقى محفوظة حتى 24 ساعة).
- كل شاشة إنتاج تُختم بـ CTA رئيسي واحد فقط.
